Choosing workforce management software for a private security company is a high-stakes operational decision. Generic human-resources software is usually built around nine-to-five office workers, while legacy security tools often require heavy manual re-keying between scheduling, timesheets, and payroll.

When evaluating a workforce platform for a South African guarding operation—particularly for fleets between 50 and 250+ guards—operators should test how the software handles real day-to-day operational exceptions rather than relying on slide-deck promises.

## 1. Does it reflect South African security rules by design?

A platform built for South African private security should treat local statutory and industry fields as native parts of the employee, leave, and payroll records—not custom text boxes bolted onto a generic template:

- **PSIRA fields:** Can you record PSIRA registration numbers and grades per guard from the moment of onboarding?
- **BCEA and NBCPSS alignment:** Does the leave module distinguish between general office staff and NBCPSS security officer leave entitlements, including public-holiday handling inside leave periods?
- **Hourly guards vs. salaried office staff:** Can the payroll workflow process pay-graded hourly guards alongside fixed-salary administrative staff in the same pay period?
- **Statutory exports:** Does the payroll pipeline support SARS exports and UIF reference tracking per period?

## 2. Are rostering, attendance, and payroll genuinely connected?

During a software demonstration, trace a single shift from start to finish:

1. Create or view a client site with day and night posts.
2. Generate a shift pattern (`3 on 3 off` or `4 on 4 off`) aligned to the company's pay period.
3. Open the site timesheet for that period—does it automatically reflect the published roster?
4. Record a reliever replacement and capture `Duty ON` and `Duty OFF` Occurrence Book (OB) numbers.
5. Attempt to calculate payroll while unconfirmed attendance entries remain open—does the system warn you and surface the blockers clearly?

> If you have to export a CSV from the rostering module just to import it into the attendance or payroll module, the workflows are not truly connected.

## 3. How does the system handle permissions and data isolation?

In a growing security firm, different team members carry different responsibilities. Look for granular, per-module access control where capabilities (`View`, `Create`, `Edit`, `Delete`, `Approve`, `Export`) are assigned independently to each user. Having permission to edit a roster should never automatically grant permission to approve payroll or export sensitive financial records.

## 4. How should you structure a pilot before full commitment?

Before rolling out new software across every site, run a scoped operational pilot with clear evaluation criteria:

- **Define the scope:** Select a representative group of client sites and a complete pay period cycle.
- **Test data import:** Validate how cleanly your existing employee and site CSV records import into the system.
- **Measure exception visibility:** Track how quickly controllers and payroll administrators can identify and resolve unconfirmed shifts, leave overlaps, and coverage gaps.
- **Verify roadmap transparency:** Ensure the vendor distinguishes clearly between modules that are live today, capabilities currently in development, and planned AI features on the product roadmap.
